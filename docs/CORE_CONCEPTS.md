# Companion Platform — Core Concepts

## Назначение

Этот документ описывает основные принципы работы Companion Core.

Companion Core отвечает за сохранение состояния проектов, контекста и истории.

Core не зависит от конкретного интерфейса, модели ИИ или внешнего сервиса.

---

# Основные принципы

## State не равно сообщение

Сообщение в чате, вывод команды или отдельный commit сами по себе не являются состоянием проекта.

Они являются источниками, из которых состояние может быть сформировано.

---

## Источники данных

Companion может получать информацию из разных источников:

- ChatGPT и другие диалоги;
- GitHub;
- локальные файлы;
- VPS и другие окружения;
- логи;
- ручной ввод пользователя.

Источник должен сохраняться вместе с полученными данными.

---

# Archive Layer

Archive является слоем хранения исходных материалов.

Назначение:

- аварийное восстановление;
- сохранение первоисточника;
- повторный анализ новыми версиями агентов.

Принцип:

> Structured Memory может быть создана заново из Archive, но Archive не должна зависеть от Structured Memory.

Примеры:

- экспорт чатов;
- логи команд;
- снимки репозиториев;
- исходные документы.

---

# Extraction Layer

Extraction Layer извлекает смысл из исходных данных.

На этом этапе создаются предложения, но ещё не изменяется состояние системы.

---

# Change Proposal

Change Proposal — предложение изменения состояния.

Это промежуточный слой между анализом и принятым решением.

Агент может предложить изменение, но система не должна считать вывод агента автоматически истиной.

После проверки создаётся Decision.

---

# State

Current State — текущее известное состояние проекта.

Оно формируется из:

- Events;
- Decisions;
- Evidence;
- WorkItems;
- Snapshots.

State может иметь ручные уточнения, но такие изменения должны оставлять историю.

---

# Execution Context Binding

Состояние проекта недостаточно описывать только через знания и решения.

Companion должен сохранять также информацию о доступных возможностях выполнения действий.

Snapshot должен включать:

- Project State;
- Execution Context;
- Tool Binding.

Пример:

```yaml
execution_context:
  repository:
    name: genrudko/Plugins_AD5X

  access:
    github: true

  capabilities:
    read_files: true
    write_files: true
    run_tests: true

  last_verified:
    commit: 3b5dfc...
```

Цель:

Новый рабочий сеанс должен понимать не только:

"Что мы знаем?"

но и:

"Какие действия реально доступны?"

---

# Human Override

Человек является частью системы управления состоянием.

Ручное изменение состояния допустимо, но должно быть зафиксировано событием.

---

# Agent model

Agent не владеет состоянием.

Agent может:

- читать состояние;
- собирать данные;
- создавать предложения;
- выполнять разрешённые действия.

Но итоговое состояние принадлежит Core.

---

# MVP Core responsibilities

Первая версия Core должна уметь:

- хранить сущности;
- принимать события;
- хранить архив;
- связывать решения с доказательствами;
- создавать Snapshot;
- восстанавливать контекст проекта.
